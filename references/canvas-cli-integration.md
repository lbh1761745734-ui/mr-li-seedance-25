# 画布 CLI / MCP 接入与批量节点操作

**触发条件**：仅当用户明确准备接入即梦画布 CLI、MCP，或已要求在画布上批量建节点、改节点、迁移素材时读取。普通提示词写作、做图、审阅不加载本文件。

本文件记录实战中反复出现的平台行为与失败模式，补充[项目上下文](context-protocol.md)与[低token与输出保真](runtime-efficiency.md)，不改变任何创作规则、对白权威或声音规则。

## 零、只建不跑（默认）

视频生成按次计费且单价不低。接入画布后，助手的默认职责是把每个分段的视频节点建好、填全、连好线，生成交给创作者。

- 每次建视频节点（或一批节点）前都问用户用哪个清晰度，列出当前模型各档的报价供选择，不自行选默认；用户在同一条指令里已指定的按指定执行。
- 建节点时一次写全：模型、模式、分辨率、画幅、时长、完整提示词与全部素材/音色引用；写入后回读确认。
- 提示词绑定段里@后照抄画布上显示的节点名；节点名本身没有扩展名时不另加。
- 不执行 `node run`、样片转正片、超清/补帧等会提交生成或消耗积分的操作；`node quote` 报价只读，可用于告知预计积分。
- 交付时列出已就绪的节点（场次分段、时长、引用条数、预计积分），说明由创作者审核提示词与连线后在画布上手动生成。
- 用户明确点名节点和范围要求代为运行时：先报价，展示金额并取得确认，只运行所列节点，每个节点各配一个提交 ID；不顺手扩大到整场、整集。
- 已提交的生成可只读查询状态；结果采用与返工仍按主规则，由创作者决定。
- 图片资产（人物、场景、道具等）按已授权的资产任务生成，不受本节限制；其消耗同样在开始前说明。

## 一、画布排版（固定，与《我在非洲种水稻》画布一致）

建节点时就把坐标一起写进去，不用平台的智能布局；同一个项目整张画布都按下面的规矩排。坐标以节点左上角为准，数值按常用尺寸（图片、视频约 569×320，音频、文本 320×320）给出，节点更大时等比加大间距，保证不重叠。视频节点建好后再挪位置会清空配置，见下文二、1。

**整张画布**

- 最上方是总素材区，从上往下依次是：说明文本 →「场景」分区 →「人物」分区 →「物品」分区。三个分区上下排列、都从 x=0 开始，每区先放一个分区标题，标题下素材横排成网格，横向、纵向间距都是 640，一行约 10 个，排满换行；没有的分区不建。
- 旧版素材不删时，整体移到画布一侧的「旧版归档」区，并放一个说明文本。
- 一集一行：同一集的场次从左往右横排；下一集另起一行，放在上一集最低节点的下方并留出明显空隙。
- 每场一个区块，相邻两场的场次标题横向间距 2200。
- 新一集从哪里开始，先找用户在画布上放的标记文本，没有就问用户。

**每场区块（坐标相对本场标题）**

- (0, 0)：场次标题文本节点，写“集-场_地点”，如“7-2_驻地墙根”。
- 左列 x=0，竖排本场用到的素材，每格纵向间距 640：场景图（y=640）→ 人物（按出场顺序，一人一格）→ 音色（只给有音色的角色，没有音色不留空位）→ 道具 → 黑场等固定片段（项目使用时）。
- 本场用到的素材在本场区块里各放一份，跨场重复放；视频节点只连本场区块里的素材，不跨场连线。
- 右列 x=1040，从 y=400 开始竖排本场的视频分段节点，每段间距 640，标题写“集-场-段”，如“7-2-1”。
- 生成后的正片放在对应分段右侧同高，位置截图等放在本场区块内；不压到下一场区块，位置不够时先问用户再整体加大间距。

**命名**

- 素材节点标题用素材文件名，如“周志远_格子短袖_新版.png”；音色节点写“集-场_地点 角色音色”；黑场写“集-场_地点 黑场_2s”。
- 提示词绑定段里@后照抄画布上显示的节点名。

**摆完核对**：落盘节点快照，全画布重叠为 0，本场节点都在本场区块范围内，范围外节点坐标没有变化。

## 二、节点操作铁律

### 1. 改视频节点的坐标会清空生成配置

只传 `--x --y` 的节点编辑会把提示词、引用、模型、时长一并重置为默认。

**规则**：移动只做移动，之后立刻重写生成配置；或一次性传全套参数（模型、模式、分辨率、画幅、时长、提示词、全部引用）。

### 2. 创建 m2v 视频节点必须带引用

无引用的多模态视频节点创建会静默失败（不报错、无节点）。

**规则**：先用场景图或占位图建节点，再统一重写提示词与引用。

### 3. 删除图片节点会连带清掉引用它的视频节点引用

平台在图片消失后自动移除下游引用，表现为"提示词里还写着，但引用列表里没有"。

**规则**：换图先建新节点、重连下游、最后删旧节点；不要在重连之前删除被引用的节点。

### 4. 删除节点需三步

`node delete` 取得确认令牌 → `node delete confirm` 取得删除令牌 → `node delete --delete-token`。缺任一步不生效，且三处必须复用同一 `--update-id`。

### 5. 节点查找分页会漏读

`node find` 逐页翻取时偶发丢页，全画布统计会出现明显偏差（例如实际 370 个只报 350 个）。

**规则**：按类型分别翻页取全量，先核对总数再执行批量操作；批量前先落盘一份节点快照，后续操作以快照为准。

### 6. 读取存在抖动

同一节点连续读取，可能一次返回空提示词、一次返回正常内容。

**规则**：关键校验失败先重读，不要立刻判定数据丢失；写入后必须回读确认。

## 三、命名与引用

### 键名后缀不一致

模块里写 `.png` 后缀、节点表里不带后缀（或相反），查表会静默返回空，导致该素材不绑定也不报错。

**规则**：查表时对带后缀与不带后缀两种形式都做一次兜底匹配；绑定完成后再做一次"绑定项数 = 图片数 + 音频数"的核对。

### 文件名与内联引用

- 未连画布、给可复制全文时，提示词正文用 **@文件名**（如“林晓参考@林晓.png”）；连上画布时照抄画布节点名；
- 画布平台若支持内联引用（`{{node:xxx}}`），由平台侧维护映射，写作侧不必感知。

两种方式不混用于同一绑定段。

## 四、图像生成的模型差异

| 场景 | 建议 |
| --- | --- |
| 常规场景、道具、多人资产板 | 通用图像模型即可，2K 足够 |
| 图像局部修补（去水印、擦文字） | 部分模型对特定底图反复返回输入拒绝，换另一条模型通道往往一次通过，且单价可能更低 |
| 画面内需要精确可读的中文 | 通用图像模型会写坏字形，改用具备文字渲染能力的图像生成通道 |

被拒绝时不要连续重试同一模型同一底图，改换模型、重写描述方向，或放弃局部修补改为重做整张。

## 五、批量脚本模式

稳定做法是四段式，不要合并：

1. **快照**：按类型翻页取全量节点，落盘为 JSON（含 id、标题、坐标、宽高、状态）。
2. **定位**：按标题前缀 + 坐标区间双重判定归属，只对目标场次/分段的节点操作。
3. **写入**：逐节点编辑，每步回读确认。
4. **核对**：绑定项数、引用条数、矩形重叠、目标范围外的节点是否被误动。

### 归属判定不要只用坐标区间

同一行里不同场次的节点纵向范围会交叠；素材库里的同名资产也落在同一横坐标上。

**规则**：标题前缀优先，坐标区间只作为二次过滤；跨集移动时按标题精确筛选，不要用"y 大于某个值就算新的一集"。

### 重叠检测

宽高都没有的节点无法判重叠，先过滤掉；重叠数量必须为 0 才算排版完成。

## 六、协作边界

- 用户手动编辑过的节点**只读**，发现异常只报告、不动手。
- 批量重排、整场重连会覆盖用户的现场编辑，必须先问。
- 需要修改单段时只做定向更新，禁止运行会遍历全场的脚本。

## 七、校验清单

批量操作结束前逐项确认：

- [ ] 本轮未提交任何未经点名授权的视频生成
- [ ] 目标分段数、时长、引用条数与预期一致
- [ ] 每段"绑定项数 = 图片引用数 + 音频引用数"
- [ ] 每个分段都有一条黑场引用（如项目使用黑场）
- [ ] 排版符合「一、画布排版」：一集一行、每场一块、素材左列、分段右列
- [ ] 全画布矩形重叠为 0
- [ ] 目标范围以外的节点坐标未变化
- [ ] 已落盘最新节点快照
